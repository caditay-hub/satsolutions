## 2. Ядро

### optics.ts
- `opticsFromSensor({ swMm, shMm, fMm, nx, ny })` → `{ hfov, vfov, dfov }` (радианы), формулы ТЗ §4.2.
- `opticsFromFov({ hfovDeg, vfovDeg?, nx, ny })`. Если VFOV не задан, он выводится из соотношения сторон: `tan(V/2) = tan(H/2)·ny/nx` (квадратный пиксель, прямолинейная оптика). Результат помечается `vfovEstimated`.
- `varifocalAt({ fMin, fMax, hfovWideDeg, hfovTeleDeg, f })` — эквивалентная ширина сенсора по обоим краям диапазона, линейная интерполяция по f. Результат — `estimate`, кроме двух крайних точек.
- `sceneAt(optics, depthM)` → ширина, высота, px/m по горизонтали и вертикали.
- `depthForPpm(optics, ppm)` — максимальная глубина по оптической оси, на которой плотность ещё не ниже порога.
- Обратный расчёт: `requiredHfov(D, W)`, `requiredNx(W, ppm)`, `requiredFocal(D, W, swMm)`, `requiredFocalForPpm(D, swMm, ppm, nx)`, `coverCheck(optics, D, W, ppm)` — проверяет и охват (`sceneWidth ≥ W`), и плотность (`nx/sceneWidth ≥ ppm`).
- Вид сбоку (`sideGeometry`): высота установки H, наклон τ вниз от горизонта, высота цели h (лицо 1,6 м, номер 0,5 м, земля 0).
  - Δ = H − h. Глубина точки цели по оптической оси: `z(d) = d·cosτ + Δ·sinτ`. Горизонтальная плотность на цели = `nx / (2·z·tan(HFOV/2))` — для pinhole это строго, даже вне оси.
  - Цель на уровне h видна при горизонтальной дальности `d ∈ [Δ/tan(τ+V/2), Δ/tan(τ−V/2)]`. Если `τ ≤ V/2`, дальняя граница — до горизонта (∞). Если `τ + V/2 ≥ 90°`, ближняя граница = 0.
  - Диапазон каждого уровня = пересечение видимого участка и `z(d) ≤ depthForPpm`.
- Защита: каждая функция принимает только конечные положительные числа в допустимых пределах (`validation` в `optics.ts`), иначе возвращает `null`. Ноль и пустое значение не подставляются.

### standards.ts
- Два независимых профиля с версией: `iec62676-4:2014-mdorii-v1` (6 уровней; флаг `base` у четырёх DORI) и `iec62676-4:2025-o2dcpvs-v1` (7 уровней, группы LPDO и HPDO).
- `evaluate(profile, ppm)` → для каждого уровня `met` (`ppm ≥ порог`) и запас. Уровни разных профилей не сопоставляются.
- `ENGINE_VERSION = "cd-optics-1"`.

### query.ts
- Сериализация в URL: короткие ключи, только параметры расчёта, без персональных данных.
- Разбор: длина значения ≤ 16 символов, только конечные числа в пределах, иначе значение по умолчанию. Неизвестный профиль → 2014.
- В URL пишутся `v` (версия движка) и `std` (профиль).

## 3. Интерфейс

- Режимы: «По параметрам камеры» (прямой расчёт) и «Под задачу» (обратный). Переключатель профиля IEC 2014 / 2025, флажок «все 6 уровней» для 2014.
- Ввод камеры: «Угол по паспорту» (по умолчанию) или «Матрица и фокус, мм» (экспертный). Тип оптики: фиксированный, вариофокальный, fisheye/панорама. Для fisheye и панорамы показывается сообщение «эта модель оптики не поддерживается», расчёт не выполняется.
- Вид сверху (SVG, масштаб 1:1 с расчётом): камера, кромки поля, полосы уровней между линиями постоянной глубины (трапеции — так и выглядит pinhole-модель сверху), отметки дистанции и ширины.
- Вид сбоку (SVG): мачта H, наклон, лучи VFOV, «слепая зона» под камерой, отрезки дальности уровней на высоте цели.
- Таблица уровней: порог, «достигается / нет» на заданной дистанции, диапазон дальностей.
- Метки статуса: «паспортные данные» / «оценка» (выведенный VFOV, промежуточный фокус вариофокала).
- Кнопки: «Скопировать расчёт» (текст + ссылка), «Скопировать ссылку». Состояние → URL через `history.replaceState`, без перезагрузки и без новых записей в истории.
- Заявка: имя + телефон → `POST /feedback` (как `CostCalculator.tsx:326`), расчёт в тексте `message`. Успех показывается только после ответа сервера `ok`. Конверсия — `trackConversion("lead")`.
- Первый экран — H1 и вводный текст, без контактов (правило владельца). Блок заявки — после таблицы уровней.
- Доступность: `label` у каждого поля, слайдер + точное поле ввода, `aria-live="polite"` у итоговых чисел, цели касания не меньше 44 px.

## 4. Страница и SEO

- Серверный рендер: H1, вводный текст, как пользоваться, формулы, допущения и ограничения, FAQ, ссылки — всё в HTML. Калькулятор гидратируется поверх. Расчёт по умолчанию тоже виден в HTML (тот же код ядра на сервере).
- Метаданные через `hreflangAlternates("/tools/camera-lens-calculator", locale)` и `withOgUrl`.
- canonical без query: параметризованные варианты не индексируются как отдельные страницы.
- JSON-LD: `WebApplication` (как на `/calculator`), `BreadcrumbList`, `FAQPage` — FAQ виден на странице.
- Ссылки со страницы: `/products/type/ip-kamery`, PTZ, NVR, `/calculator`, `/solutions/cctv`, статья «как выбрать камеру». Ссылка на калькулятор с `/calculator` и `/solutions/cctv` — в этом же выпуске.
