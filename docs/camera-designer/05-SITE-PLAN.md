# SAT Camera Designer — этап C: план объекта (10.11.2026)

Вкладка «План объекта» на странице `/tools/camera-lens-calculator` (×5 языков, `#plan` в адресе). Калькулятор остаётся первой вкладкой и по-прежнему рендерится на сервере. Редактор плана грузится отдельным чанком при первом открытии вкладки (`next/dynamic`, `ssr: false`).

## Решения владельца (10.11)

| Вопрос | Решение |
|---|---|
| Где | Вкладка в калькуляторе, не отдельная страница |
| Форматы | PNG/JPG + PDF в браузере (pdf.js 4.10.38, legacy-сборка, Apache-2.0), выбор страницы PDF |
| Геометрия | С высотой и наклоном (плоскость цели, слепая зона, дальний край) |
| Преграды | Стены режут обзор (2D, с пометкой «2D-оценка») |
| Камеры | Из каталога (verified и needs_review с пометкой) + своя камера |
| Анализ | Зоны уровней цветом, зона охраны и % покрытия, перекрытия, список камер с ценами |
| Хранение и экспорт | Автосохранение в браузере (IndexedDB), файл `.satplan`, PNG, печать / PDF через браузер |
| Заявка | Текст + картинка плана по галочке, через `/chat/upload-file`, как файл в форме КП (ссылка со случайным UUID) |
| Наклон | Высота установки (по умолчанию 3 м) + точка, куда смотрит ось (перетаскивается мышью или пальцем) |
| Телефон | Полное редактирование пальцем |
| Лимиты | Файл до 30 МБ, картинка до 4096 px по длинной стороне, до 64 камер |

План на сервер не уходит. Исключение — картинка плана, которую клиент сам приложил к заявке.

## Модель (`lib/cameraDesigner/plan/`)

- **Координаты** — метры плана: x вправо, y вниз, z вверх. Курс — от +x по часовой стрелке, наклон — вниз от горизонта.
- **Плоскость цели** на высоте `targetM`. По умолчанию 1,6 м (лицо), как в калькуляторе. Плотность пикселей по IEC 62676-4 относится к объекту, а не к полу.
- **Точка в кадре:** глубина по оптической оси `z = v·f`, координаты кадра `u = v·r/z`, `w = v·up/z`. Точка видна, если `|u| ≤ tan(H/2)` и `|w| ≤ tan(V/2)`. Плотность `= Nx / (2·z·tan(H/2))` — та же формула, что в калькуляторе.
- **Вектор.** Глубина точки плоскости на луче `(u, w)` равна `dh / (sin τ − w·cos τ)` и от `u` не зависит. Поэтому граница «глубина = D» — горизонтальная линия кадра, а полоса уровня на плоскости — точная трапеция (`band`, `depthEdge`).
- **Растр:** `analyze()` в веб-воркере.
  - Сетка до 220 000 клеток; во время перетаскивания — 40 000.
  - Для PNG, печати и вложения в заявку — до 1,2 млн клеток.
  - Для каждой клетки считается лучший уровень и число камер; стены — проверкой пересечения отрезков.
- **Покрытие зоны** — по клеткам внутри многоугольника: доля площади на каждом уровне, «не покрыто ни на одном уровне», перекрытие (видят ≥ 2 камеры).
- **Зум** (вариофокал, PTZ):
  - края диапазона — паспортные углы;
  - промежуточный фокус — модель `varifocalAt` калькулятора, с пометкой «оценка»;
  - без фокуса в данных — линейная интерполяция `1/tan(H/2)`.

Тесты `plan/plan.test.ts` (19):
- глубина и плотность сверены с видом сбоку калькулятора, слепая зона — с `sideGeometry`;
- трапеция уровня и линия уровня;
- обратный расчёт наклона;
- стены, площадь и принадлежность точки многоугольнику;
- покрытие простых сцен: 100 % / 0 %, тень от стены, перекрытие двух камер, площадь по сетке с точностью до 3 %;
- оптика зума;
- строгий разбор файла проекта и отказ на испорченных данных.

## Камеры каталога

`GET /api/camera-designer/cameras` — компактный список камер с углами: 273 штуки (verified и needs_review с известным кадром). Ссылок на документы производителя в ответе нет; `noindex`, кэш на час.

`GET /api/camera-designer/cameras?slugs=…&locale=` — название на языке страницы, цена в сумах, наличие и фото для таблицы под планом. Принимаются только slug из списка, не больше 64; иначе ответ 400.

В проект копируется снимок углов камеры, поэтому файл откроется, даже если карточку потом изменят.

## Файл проекта `.satplan`

JSON `{ format: "sat-camera-plan-file", project, image }`.
- `image` — data:-URL PNG, JPEG или WebP либо `null` (план-сетка без картинки).
- При открытии файла проверяются: тип по первым байтам, формат и версия, диапазоны всех чисел, лимиты (64 камеры, 500 стен, 20 зон по 200 точек), уникальность id камер, размеры картинки против `bg`.
- Внешние ссылки на картинки не принимаются.

## Безопасность

- Тип загружаемого файла определяется по первым байтам (PNG, JPEG, `%PDF`, JSON), а не по расширению.
- PDF открывается с `isEvalSupported: false` и `enableXfa: false`: скрипты документа не выполняются.
- Картинка перерисовывается через canvas, поэтому метаданные исходного файла в проект не попадают.

## Ограничения (видны клиенту)

- 2D-оценка: стены сплошные на всю высоту; мебель, деревья, рельеф, освещение и сжатие видео не учитываются.
- Многосенсорные камеры, fisheye и тепловизоры в список камер плана не попадают (`unsupported` на этапе B0).
- Отмены последнего действия (undo) нет — удаление камеры, стены или зоны выполняется кнопкой.
- Колесо мыши над планом меняет масштаб, а не прокручивает страницу; на телефоне палец на плане двигает план (`touch-action: none`). Страница прокручивается за пределами полотна.
