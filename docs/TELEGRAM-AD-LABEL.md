# Метка рекламного клика для обращений через Telegram

Дата: 17.11.2026. Ветка `claude/dazzling-pascal-0a013e`. **Ничего не выложено: рабочий сайт, сервер, бот и CRM не менялись.** Выкладка, миграция и перезапуск бота — только после «да» владельца.

Основание: решение владельца от 16.11.2026 — вариант «бот только для посетителей с рекламы» (в `docs/GCLID-CHAT-TELEGRAM-PLAN.md` это Т3, в `SAT_GOOGLE_ADS_RANK_OPTIMIZATION/13_TELEGRAM_ATTRIBUTION.md` — вариант А).

## Что изменится

| Кто | Сейчас | После выкладки |
|---|---|---|
| Посетитель, пришедший по рекламе Google (в последние 90 дней) | кнопка Telegram открывает рабочий аккаунт @sales_satsolutions | кнопка Telegram открывает бота @SAT_zayavki_online_bot; человек нажимает «Старт», видит короткое приветствие «вам ответит менеджер» и пишет вопрос; отвечает тот же менеджер из группы |
| Все остальные посетители | рабочий аккаунт @sales_satsolutions | без изменений |
| Менеджеры | тема в группе и обращение в CRM | то же самое; в карточке новой темы видно страницу сайта, с которой нажали кнопку, и строку «Источник: Google Ads · кнопка Telegram на сайте» |
| CRM | у обращений из Telegram рекламный источник не известен ни у одного | у обращений, пришедших этим путём, заполняется метка клика — так же, как у форм и чата сайта |
| Google Ads | конверсия «Telegram (клик)» считается по нажатию | считается так же: событие уходит до перехода и не зависит от того, куда ведёт ссылка |

Внешний вид сайта, тексты и адреса страниц не меняются. В HTML ссылка по-прежнему ведёт на рабочий аккаунт; подмена происходит в момент нажатия и только у посетителя с меткой клика. Для поисковых систем ничего не меняется.

## Как это работает

1. Посетитель с меткой клика нажимает кнопку Telegram. Сайт создаёт случайный код из 12 букв и цифр, отправляет на свой сервер пару «код → метка клика» и подменяет адрес ссылки на `t.me/SAT_zayavki_online_bot?start=g_<код>`.
2. Человек нажимает «Старт» в боте. Бот получает код, спрашивает у сервера сайта метку по этому коду и запоминает её за диалогом.
3. Человек пишет сообщение. Бот заводит обращение в CRM уже с меткой клика. В CRM ничего менять не нужно: приём обращений метку записывать умеет.

## Что хранится

Таблица `telegram_clicks` в базе сайта: код, метка клика, адрес страницы без параметров, время нажатия, время первого запроса бота. Имён, телефонов и переписки в ней нет. Записи старше 90 дней удаляются сами — при каждом запуске API сайта и раз в сутки.

Побочная польза: по полю «время первого запроса бота» впервые видно, сколько людей после нажатия действительно открыли бота.

## Допущения, принятые при разработке

1. Подменяются только ссылки на `t.me/sales_satsolutions`. Другие ссылки Telegram, если появятся, не затрагиваются.
2. Один код на вкладку браузера и метку клика: повторные нажатия новых записей не создают.
3. Код действует 90 дней и может быть запрошен ботом повторно — Telegram присылает его снова, если человек ещё раз откроет ту же ссылку.
4. Адрес приёма кода назван `/tg-ref`, без слова click: адреса со словом click режут блокировщики рекламы.
5. Если запись до сервера не дошла — блокировщик, превышен лимит — обращение приходит без метки, как сейчас. Потери обращения нет.
6. У диалога сохраняется первая метка. Если человек уже писал боту раньше, к его диалогу добавляется только метка; страница и тема остаются прежними.
7. Нажатие колёсиком мыши и «открыть в новой вкладке» из меню ссылку не подменяют. Конверсия по таким нажатиям не считается и сейчас.
8. Клики с iPhone, у которых вместо обычной метки приходит `gbraid` или `wbraid`, не охвачены — сайт их не читает и в формах.
9. Посетитель с рекламы попадает на бота все 90 дней, пока жива метка в его браузере, в том числе при повторном заходе напрямую.

## Шаги выкладки — каждый только после «да»

**0. Подготовка.** Проверить, нет ли в `origin/main` чужих коммитов; влить ветку в `main` только перемоткой вперёд; `git push`.

**1. Бот.** До выкладки сайта эта правка ничего не меняет: код в `/start` прийти ещё не может.

```bash
ssh satweb-prod 'cd /root/sat-web-bot && sha256sum index.js'
```

Ожидается `a711cea9…a62348` — с этой версии снят файл правки. При другой сумме остановиться: файл на сервере менялся.

```bash
scp docs/tg-ref/sat-web-bot.tg-ref.diff satweb-prod:/root/sat-web-bot/tg-ref.diff
```

```bash
ssh satweb-prod 'cd /root/sat-web-bot && cp index.js index.js.bak-tgref-$(date +%Y%m%d-%H%M%S) && patch --dry-run -p2 < tg-ref.diff && patch -p2 < tg-ref.diff && node --check index.js && pm2 restart sat-web-bot'
```

Сначала сухой прогон правки, затем запись; синтаксис проверяется до перезапуска. Проверка после: `pm2 logs sat-web-bot --lines 30` — подключение к сайту и отсутствие ошибок.

**2. Сайт и API.** `npm run deploy` из корня репозитория после `git push`. Миграция 059 применяется сама при запуске `sat-api`. Проверка: коммит на сервере совпадает; таблица `telegram_clicks` создана; в логах `sat-api` нет ошибок.

**3. Проверка на рабочем сайте.** Нужна отдельная договорённость: чтобы увидеть метку в CRM, придётся создать одно тестовое обращение с пометкой «тест».

**4. Через 30 дней.** Сколько обращений из Telegram получили метку; сколько нажатий закончились открытием бота.

| Что | Как | Время |
