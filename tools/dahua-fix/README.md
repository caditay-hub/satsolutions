# Исправление фото/категорий товаров Dahua

Пакет данных и скрипт для исправления **несоответствия фото товарам Dahua** на сайте.

## Суть проблемы

В прайс-листе (`DAHUA_PRICE_new.xlsx`) фото — это картинки, встроенные в колонку B и
**растянутые на 2–3 строки**. При первоначальном импорте фото привязывались к товару по
верхней границе изображения (`from.row`), из-за чего у многих товаров фото «съехало» на
соседа. Пример: металлоискатель `DHI-ISC-H001` получил фото внутреннего монитора.

## Как получено правильное сопоставление

Фото привязано к товару по **вертикальному центру** каждого изображения (с учётом высот
строк и смещений EMU), а не по верхней границе. Это сопоставление проверено вручную на
нескольких товарах (металлоискатель, 4G-камера на солнечной батарее и др.).

## Содержимое

| Файл | Описание |
|---|---|
| `DAHUA_PRICE_new.xlsx` | исходный прайс (источник истины) |
| `images/<код>.<ext>` | 228 фото, переименованных по коду товара (правильная привязка) |
| `dahua_products.json` | данные для скрипта: код, нормализованный код, цена, категория (эвристика), предлагаемое имя, файл фото, флаг |
| `dahua_mapping.csv` | то же в читаемом виде для ревью человеком |
| `fix-dahua.mjs` | скрипт, обновляющий БД |

### Поле `image_flag`
- `ok` (216) — в строке ровно одно фото по центру, привязка однозначна.
- `multi` (8) — в прайсе несколько фото (варианты); взято первое.
- `nearest` (4) — фото по центру нет, выбрано ближайшее. **Стоит проверить вручную.**

### Категории
В прайсе **нет** колонки категорий — `category_guess` определена эвристикой по описанию.
21 товар — «Не определена». Категории и предлагаемые имена **рекомендуется проверить** по
`dahua_mapping.csv` перед применением с флагами `--categories`/`--names`.

## Запуск

Нужен доступ к боевой БД (`DATABASE_URL`) и пакет `pg` (есть в `apps/api`).

```bash
# 1) сначала dry-run — ничего не меняет, печатает план:
DATABASE_URL=postgres://user:pass@host:5432/db node tools/dahua-fix/fix-dahua.mjs

# 2) применить только фото (безопасно, основная задача):
DATABASE_URL=... node tools/dahua-fix/fix-dahua.mjs --apply

# 3) дополнительно категории и/или имена (после ревью CSV):
DATABASE_URL=... node tools/dahua-fix/fix-dahua.mjs --apply --categories --names
```

Доп. переменные: `UPLOADS_DIR` (куда класть картинки, по умолчанию
`apps/api/uploads/images`), `PUBLIC_PREFIX` (URL-префикс, по умолчанию `/uploads/images`).

## Сопоставление товаров

По **нормализованному коду**: верхний регистр, удаляется «DAHUA» и ведущий префикс
`DH-`/`DHI-`, остаются только буквы и цифры. Сравнивается со `slug`, кодом из `name` и
значениями `characteristics` товара. Пример: `DH-KIT/BP4A-4G/M0508` и slug
`dahua-kit-bp4a-4g-m0508` → оба `KITBP4A4GM0508`.

## Примечания
- Скрипт по умолчанию работает в **dry-run**. Всегда проверяйте вывод перед `--apply`.
- Схема боевой БД может отличаться от этого репозитория — скрипт определяет имена колонок
  автоматически и печатает их; категории/имена меняет только по явным флагам.
- Если боевой код сайта в другом репозитории — данные (`images/`, `dahua_products.json`)
  переносимы, нужно лишь адаптировать `fix-dahua.mjs` под вашу схему.
