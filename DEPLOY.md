# Деплой satsolutions

## Поток работы (local → GitHub → сервер)

1. **Правишь код локально** в `D:\sat_web_github` (сайт на http://localhost:3000 обновляется сам).
2. **Сохраняешь в GitHub:**
   ```powershell
   git add -A
   git commit -m "что изменил"
   git push
   ```
3. **Выкатываешь на боевой сайт (по кнопке):**
   ```powershell
   npm run deploy
   ```
   Эта команда заходит на сервер по SSH-ключу и запускает деплой:
   `git reset --hard origin/main` → `npm install` → `build` → `pm2 reload`.

> Пуши можно делать сколько угодно — на прод ничего не уезжает, пока ты сам не запустишь `npm run deploy`.

## Что важно знать

- **Источник правды — GitHub.** Деплой приводит сервер ровно к состоянию ветки `main`.
  Любые правки, сделанные напрямую на сервере, при деплое **сохраняются в `git stash`**
  (как бэкап) и заменяются версией из GitHub. Не редактируй на сервере — редактируй локально и пушь.
- **Секреты (`.env`) на сервере не трогаются** — они не в git, у сервера свои.
- **Чужие сервисы** (`sat-crm-*`, боты) деплой не трогает — перезапускаются только
  `sat-api`, `sat-web`, `sat-admin`.
- **Если что-то сломалось после деплоя** — откати коммит и выкати снова:
  ```powershell
  git revert HEAD
  git push
  npm run deploy
  ```

## Доступы

- `ssh satweb-prod` — вход на сервер по ключу (алиас в `~/.ssh/config`).
- Серверный скрипт деплоя: `/root/deploy-satweb.sh` (копия — `scripts/deploy.sh`).
  Если меняешь `scripts/deploy.sh`, синхронизируй: `npm run deploy:push-script`.
