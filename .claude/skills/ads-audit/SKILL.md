## ЧЕМ ДИАГНОСТИРОВАТЬ (порядок)
1. **`ad_group_ad.action_items`** — Google прямо пишет, что чинить в объявлении («Try including more keywords in your headlines»). ГЛАВНЫЙ инструмент по силе объявлений.
2. **`campaign.primary_status_reasons`** — `["AD_GROUPS_PAUSED"]` мгновенно находит кампании-пустышки (включена, а все группы на паузе). Проверять ПЕРЕД любой правкой кампании, иначе работа уходит в пустоту.
3. **`campaign_conversion_goal`** — ⚠️ ставками управляет ОН, а не галочка `primary_for_goal` у действия. Прецедент: «Telegram (клик)» имел `primary_for_goal=false` и `include_in_conversions_metric=false` (в UI «вторичный»), но категория CONTACT была biddable на уровне кампании → клики по иконке давали **55% сигнала Shopping и 43% «Услуг»**. Проверять цели кампании, не флаг действия.
4. Полный аудит: `node /root/sat-analytics/deep_audit.cjs` — 16 секций, вывод в файл, читать секциями. ⚠️ Включает REMOVED-кампании: фильтровать.
5. `recommendation` по RSA ПУСТ (0 строк) — не полагаться. Поля `recommendation.responsive_search_ad_recommendation.ad` в v22 НЕТ.

## Грабли GAQL
Несовместимые поля дают НЕ ошибку, а **пустой результат** — ловится сравнением с урезанным запросом:
- `metrics.search_budget_lost_impression_share` в `keyword_view` → 0 строк (потери считаются для кампаний/групп).
- `ad_group_criterion.quality_info.*` + `segments.date` → 0 строк (качество брать отдельным запросом без дат).
- `metrics.cost_micros` + `segments.conversion_action_name` → 0 строк.
- `campaign_asset` + фильтр `campaign.status` → 0 строк (фильтровать по `campaign_asset.status`).
А вот эти дают ЯВНУЮ ошибку 400:
- `geographic_view` и `user_location_view` требуют **`campaign.id` в SELECT**.
- `campaign_asset`/`ad_group_asset` тоже требуют `campaign.id` в SELECT.
- `DURING LAST_60_DAYS` не существует — только 7/14/30 дней либо `BETWEEN 'дата' AND 'дата'`.
⚠️ Полный текст ошибки виден только при `txt.slice(0, 2000)`; при 300 символах обрезается до бесполезного «Request contains an invalid argument».
⚠️ Счётчики ключей завышены: критерии УДАЛЁННЫХ групп остаются в выдаче. Всегда добавлять `AND ad_group.status = 'ENABLED'`.

## Грабли мутаций
- Ответ https в Node склеивать ТОЛЬКО через `Buffer.concat` — `b += chunk` рвёт UTF-8 на границах чанков.
- Минус-слова матчатся по ЦЕЛЫМ словам без словоформ: PHRASE-минус «гост» НЕ блокирует «гостиница». Конфликты искать по токенам, не подстрокам. И групповой минус действует ТОЛЬКО в своей группе — наивная проверка даёт ложные срабатывания.
- Перенос групп между кампаниями невозможен — только пересоздание (объявления идут на повторную модерацию, история остаётся у старой группы). Порядок: создать группу → залить ключи → создать объявление → и только потом удалять источник.
- Имена групп уникальны внутри кампании.
- Правка RSA: `ads:mutate` с updateMask `responsive_search_ad.headlines,responsive_search_ad.descriptions` — пересоздавать не нужно, уходит на авто-перемодерацию.
- Ad Strength после правки становится PENDING и **не пересчитывается, пока кампания не показывается**.
- Удаление кампании необратимо. ПЕРЕД удалением обязательно сверять уникальность ключей (`/root/overlap.cjs`) — иначе теряется семантика.

## ⛔ ПРАВИЛА РАБОТЫ
1. **Запуск кампаний, повышение бюджетов, изменение стратегии ставок — ТОЛЬКО после явного «да» на конкретное действие** с озвученной суммой. Подготовить → показать → спросить.

4. Не выдумывать правки к тому, что объективно в порядке (проверено на группе «B2B — гостиницы»: и объявление, и страница были хороши, низкий QS оказался устаревшей оценкой при малой статистике).
5. Биллинг в API НЕ виден: `billing_setup` показывает APPROVED, кампании ELIGIBLE, а показов нет. Простой из-за долга ловится только обрывом показов по дням (`segments.date`).
